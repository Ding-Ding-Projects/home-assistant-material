Private vocabulary file and drop to applyBuilt and seen working in a running instance. A card on Profile, Localization chooses, replaces or clears a JSON file (schema version 1, up to 256 KiB, UTF-8); a file can also be dropped anywhere in the window. The file is checked in full first: size, encoding, nesting depth, duplicate keys, unsafe keys, unknown fields, version, key and value lengths, control characters. A file that fails changes nothing and the message names the kind of problem without repeating anything from the file. Wording is applied where text is localized, so addresses, paths, identifiers and stored names stay literal. Only the checked entries are cached in the browser; nothing about the file is kept and nothing is sent anywhere. A short confirmation shows after a load. Checked by 31 unit tests. Base64 toolkitBuilt and seen working in a running instance beside the board (docs/screenshots/base64-toolkit.png). A Base64 tab under Tools encodes text or a file, decodes it back, and writes data URLs, with the Standard, URL-safe and MIME alphabets, padding on or off, lines of 64 or 76 characters, and text read as UTF-8 or Latin-1. Each encoding is decoded again and compared, with a SHA-256 of both. Strict decoding stops at the first character that does not belong and says where; lenient decoding skips it. A file over 1 MB is encoded in pieces with pause and cancel, and saved as a file: a 3 MB file was encoded in four pieces and the saved text decoded to the same file outside the browser. Everything happens in the browser.Base64
